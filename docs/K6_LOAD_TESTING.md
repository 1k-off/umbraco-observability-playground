# k6 load testing

Scenarios, thresholds, and integration with the monitoring demo. Directory: `load/k6/`.

---

## Goals (Phase 6 — after instrumentation)

k6 is implemented **after** K8s apps, the observability stack, and OTel/Faro/Alloy (Phases 3–5). The suite is **full load testing**, not smoke-only.

1. **SLO validation:** smoke, load, stress, spike, and cms-direct scenarios with thresholds (see scenario table below).
2. **Observability correlation:** under `load.js`, prove RPS/p95/errors in Mimir, traces in Tempo, `trace_id` in Loki, profiles in Pyroscope, Faro sessions (optional `browser.js`).
3. **Baseline:** record RPS, p95, error rate in `docs/BASELINE.md` for the instrumented k8s environment.
4. **Incident demo (Phase 7):** scenarios with `slow` / `fault` endpoints enabled.

## Traffic mix (load.js)

Mixed workload simulating readers:

| Operation | Weight | Endpoint |
|-----------|--------|----------|
| Home | 25% | `GET /` |
| Article list | 25% | `GET /articles?page=N` |
| Article detail | 30% | `GET /articles/{slug}` — slug from seed pool |
| Search | 15% | `GET /search?q={term}` |
| About | 5% | `GET /about` |

**Slug pool:** load from CMS in `setup()` or use fixed JSON `load/k6/data/slugs.json` (generated by seed script).

**Search terms:** `load/k6/data/search-terms.json` — 20 terms from seed.

## Thresholds

### smoke.js

```javascript
thresholds: {
  http_req_failed: ['rate<0.01'],
  http_req_duration: ['p(95)<2000'],
}
```

### load.js (baseline — tune after first run)

```javascript
thresholds: {
  http_req_failed: ['rate<0.02'],
  http_req_duration: ['p(95)<1500'],
  'http_req_duration{page:home}': ['p(95)<1200'],
  'http_req_duration{page:search}': ['p(95)<2000'],
}
```

Record actual values in `docs/BASELINE.md` after Phase 6 (first full runs on k8s).

### stress.js

- No strict p95 — goal is to find degradation point
- `http_req_failed` < 5% until knee point (document)

## Example smoke.js structure (pseudocode)

```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';

const BASE = __ENV.K6_WEB_BASE_URL || 'http://localhost:3000';

export const options = {
  vus: 3,
  duration: '1m',
  thresholds: { http_req_failed: ['rate<0.01'] },
};

export default function () {
  const res = http.get(`${BASE}/`);
  check(res, { 'home status 200': (r) => r.status === 200 });
  sleep(1);
  // + articles, search, health
}
```

Agent implements full scripts in **Phase 6** (all scenarios in the table above, plus `lib/` helpers and `data/` fixtures).

## Demo incident scenarios (Phase 7)

### Slow endpoint

1. Enable `Demo__SlowEndpoint=true` on CMS
2. Run `load.js` for 5 min
3. In Grafana: p95 rise on `umbraco-cms`, span `demo.slow`

### Fault endpoint

1. Enable `Demo__FaultEndpoint=true` (10% 500)
2. Run `load.js`
3. Alert `HighErrorRate` firing; Loki error logs; Tempo error spans
